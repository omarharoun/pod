# Pod

Small-group accountability for people stuck in a rut. You name one thing you've been
putting off, say how much you can realistically give, and get matched into a pod of two or
three people with the same goal, the same effort level, and an overlapping timezone. Each
week the pod has one small action. Each member posts a ten-second proof. The pod sees who
is in. The proof disappears at the end of the cycle. The streak belongs to the pod.

The thesis is that ruts break through low-stakes social witness, not motivation — so the
product never shames anyone, never shows an individual score, and never keeps your proof
longer than the week it belonged to. Those aren't features; they're constraints, and they
are written down in [`CLAUDE.md`](CLAUDE.md) §2.

## Layout

```
CLAUDE.md            the brief — product rules, workflow, the two algorithms
docs/DECISIONS.md    ADR log, append-only. Read before any architectural change.
docs/VERIFYING.md    what is verified and what is not, and how to check the rest
docs/API.md          generated from the spec
content/microcopy.json   every user-facing string, on every platform
design/tokens.json   colour, type, spacing — platform-agnostic
backend/openapi.yaml the contract. Changes here drive both clients.
backend/             Go service (ADR-001)
ios/                 Swift 6 / SwiftUI, iOS 17+
android/             Kotlin / Compose / Material 3, API 26+
tools/codegen        spec + copy + tokens -> Go, Swift, Kotlin, docs
tools/copylint       mechanical enforcement of the never-shame rule
```

Three sources of truth, and everything downstream of them is generated:

| Source | Generates |
|---|---|
| `backend/openapi.yaml` | wire models for all three platforms, `docs/API.md` |
| `content/microcopy.json` | typed copy keys + the bundled catalogue each client ships |
| `design/tokens.json` | typed colour / spacing / type constants for both clients |

Never edit a file with a `Code generated by` header. Change its source and run
`make generate`.

## Working on it

```bash
make help          # what's available
make generate      # regenerate everything downstream of the three sources of truth
make verify        # spec check + copy lint + backend tests
```

`make verify` is everything that runs on a Linux box. The iOS and Android builds need
macOS with Xcode 16 and the Android SDK respectively.

### Backend

```bash
createdb pod_dev
export DATABASE_URL=postgres://localhost/pod_dev?sslmode=disable
make migrate
make backend-run          # http://localhost:8080/v1/health
make backend-test
```

`go test ./...` runs the unit tests with no dependencies. Set `TEST_DATABASE_URL` to also
run the integration tests against a real Postgres; without it they skip and say so.

### iOS

```bash
cd ios
xcodegen generate        # project.yml -> Pod.xcodeproj (the project file isn't committed)
open Pod.xcodeproj
```

`PodKit` is a plain Swift package and its tests run without a simulator:
`swift test --package-path ios/PodKit`.

### Android

```bash
cd android
./gradlew :app:assembleDebug
./gradlew test
```

**Installing it on a phone.** `:app:assembleDebug` produces
`android/app/build/outputs/apk/debug/app-debug.apk`, signed with the standard debug key, so
it installs on a device with "install unknown apps" allowed. Every CI run keeps one as an
artefact, downloadable from the run page.

By default a debug build points at `http://10.0.2.2:8080`, which is the *emulator's* alias
for your host machine and means nothing on a real phone. Tell it where the backend is:

```bash
./gradlew :app:assembleDebug -PpodApiBaseUrl=http://192.168.1.5:8080   # or POD_API_BASE_URL
```

That address has to be reachable from the phone — the machine's address on the same
network, not `localhost`. Cleartext HTTP is permitted for the debug build only; a release
build sends a session token on every request and will not send one over plain HTTP.

## Milestones

M1 contract + auth · M2 onboarding + matching · M3 the week loop · M4 ephemerality +
notifications · M5 recovery + dissolution · M6 cycle completion · M7 paywall.

M3 is the product. Nothing after it starts until it feels finished on both platforms.

**Where we are: M1 through M7 are built.** Sign in, name the thing you've been putting off,
wait for the next matching window, land in a pod, and then every week: one small action,
ten seconds of proof, and a ring that closes only when everyone is in. Proof is deleted
when the week closes, server-side, and there is a test that says so. Past that: a missed
week that offers a smaller rung rather than a verdict, a pod that winds down and puts
everyone back in the pool, a six-week cycle that graduates, and a second lane you can buy
for a second thing.

Every operation in `openapi.yaml` is implemented. Nothing answers `501` any more.

Built is not the same as run. `docs/VERIFYING.md` says exactly what has been executed, by
what, and what is left — read it before trusting any of the above.

Two scheduled jobs, neither of which ever runs on request (`CLAUDE.md` §5):

```bash
make backend-run                        # the API
cd backend && go run ./cmd/matcher once # one matching window
cd backend && go run ./cmd/weekly once  # turn weeks over, sweep expired proof
```

Both take `serve` instead of `once` to run on their own schedule.

One more, run by hand rather than on a schedule:

```bash
cd backend && go run ./cmd/reembed      # after any change to internal/embed (ADR-031)
```

A stored goal vector is the output of whatever the embedder was on the day it was saved.
Change the lexicon and every vector is stale — `embed.Similarity` answers 0 for a stale
width, so the signal drops out rather than going wrong, and this is how it comes back.
`--dry-run` reports what would change without writing.
